# YouTube channel video inputs

This endpoint lists regular uploads only. Shorts, live/past streams, playlists and community posts are separate content surfaces; no input here switches to them. A completed regular-upload walk does not establish coverage of those surfaces.

The empty top-level required list is qualified by allOf/anyOf: channelId or handle is required. Both may be supplied without inventing precedence or resolving one from the other. The helper validates declared properties/types/enums, nonempty identifiers, handle without @ and cursor exclusion; backend owns detailed ID/date/feature syntax. Omitted fields stay omitted.

| JSON / CLI | Type | Meaning |
| --- | --- | --- |
| `handle` / `--handle` | string | Channel handle without @. Preserve exact supplied string; no automatic ID resolution or URL parsing. |
| `channelId` / `--channelId`, `--channel-id` | string | Channel ID, preserved with exact casing; no formal prefix/length pattern declared. Not channel_id, pageId or a URL field. |
| `sort` / `--sort` | latest/popular | Native ordering, preserve omission/choice and returned order. No sortBy/sort_by or local view re-ranking. No since/sort incompatibility specified here. |
| `async` / `--async` | boolean/integer/string | Exact JSON variants: booleans, integers 0/1, strings "true"/"false"/"1"/"0". CLI true/false becomes boolean, 1/0 integer. Independent of fixed response_mode=json. |
| `since` / `--since` | string | Inclusive midnight UTC date or ISO timestamp. Older videos omitted; older non-pinned entry ends walk with stopped_at=since and no next cursor. Pins never stop it. CLI --published-after/--start-date/--from-date map here. |
| `until` / `--until` | string | Inclusive whole UTC date or ISO timestamp. Filters newer rows, keeps undated rows and does not stop walk. CLI --published-before/--end-date/--to-date map here. |
| `cursor` / `--cursor` | string | Exact pagination.next_cursor from compatible prior response, mapped to continuationToken by API. Omit for page 1. No decoding, construction, arithmetic, integer coercion or automatic paging. |
| `continuationToken` / `--continuationToken`, `--continuation-token` | string | Native continuation token from compatible response. Prefer universal cursor; never send both (helper rejects ambiguity). |
| `stop_at_id` / `--stop-at-id` | string | Known newest post.id/post.url. Stops before a non-pinned match and following rows, stopped_at=known_id/no next cursor. Pins never trigger it. Absent match leaves full page/cursor; end means exhausted, null means more may remain. Preserve ID/URL string. |
| `include` / `--include` | string channel | Explicit one-channel lookup per page for subscriber count, missing display_name/avatar/channel_id and owner country. No engagement or CSV token, no automatic enabling and no username guarantee. Preserve data.hydration/nulls. |
| `exact_dates` / `--exact-dates` | string true/false | Shared free default true; channel/videos dates are already exact, so lookup here also attempts creator-original titles and updates computed.language. False skips lookup without making already-exact dates approximate. Preserve original_titles_partial/unavailable warnings and native title/precision markers. Strings, not booleans. |
| `includeExtras` / `--includeExtras`, `--include-extras` | string | True explicitly adds likes/comments/description, with latency. No enum declared; preserve string, backend validates detailed values. Not needed for default exact dates; no channel/duration side effects specified here. |
| `is_paid_promotions` / `--is-paid-promotions` | string | True explicitly selects publicly disclosed paid product-placement/sponsorship/endorsement videos. Normal videos, not an inferred model label. Other string meanings are backend-owned; false/omission does not establish absence of undisclosed promotion. No automatic enabling or local classification. |

One operation returns one page without helper continuation, channel/per-video reads or media downloads. Explicit next page uses new state/client ID, exact opaque cursor and unchanged identifiers/options; retain cursor provenance. READY finishes a task, not full channel history while continuation remains. Date filtering retains normal page price. Since/known-ID pin exemptions and native stop/cursor metadata are authoritative; do not reapply local date/pin filtering. Until can leave empty pages with continuation. Saved completion is a snapshot; an explicitly requested fresh daily check uses a new state/client ID and selected date/known-video boundary.

Include channel is described as one lookup/1 credit for the entire page, refunded if unreadable and free when recently cached; it adds normally under a second, never more than 8. Read native data.hydration and accounting rather than billing per row or retrying unresolved IDs. Above 1000 subscribers, the returned figure is rounded to three significant digits. Country is owner-set and can be null, not filming location or a reason for local filtering. Missing author username is not promised to be filled by this option.

The shared exact_dates description discusses relative dates on other routes, but explicitly says channel/videos dates are already exact. Preserve actual native timestamps, title_maybe_translated, published_precision/published_label if present, computed.language and original-title warnings without inferring a corrected title/language. Exact_dates=false skips the lookup; includeExtras is independent. The description mentions a per-video detail route without its schema: do not invent a follow-up call or automatically fetch it.

Static date aliases are CLI-only; JSON accepts exact schema names, including camelCase. Resolve requested relative dates into explicit since/until before invoking with timezone/date context and persist the chosen literals on retries. No query, type, channel_id, sortBy/sort_by/sort_rows, limit, trim, labels, judgments, fit, relevance, dry_run, max_age_days, region, country or media controls are declared. Do not import search/Shorts-specific options or channel-enrichment pricing from other helpers.
