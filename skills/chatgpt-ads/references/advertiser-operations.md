# Using the advertiser operations

Use the bundled `chatgpt_ads.sh` wrapper for the commands below. `operations` lists available names. `describe NAME` shows the fixed method and path, path parameters, supported query names, body fields and required inputs. Read operations accept `--output` to save native JSON. Mutations use `plan` followed by the existing `execute --state FILE --confirm FINGERPRINT`. Keep one receipt per intent. Show the account, current settings, exact proposed values, affected IDs and expected delivery or data effects before requesting consent.

```bash
bash <skill-path>/scripts/chatgpt_ads.sh read list-campaigns --query ./search.json --all-pages
bash <skill-path>/scripts/chatgpt_ads.sh describe update-campaign
bash <skill-path>/scripts/chatgpt_ads.sh plan update-campaign --param campaign_id=CAMPAIGN_ID --body ./budget.json --state ./change.json
bash <skill-path>/scripts/chatgpt_ads.sh execute --state ./change.json --confirm FINGERPRINT
```

For the first example, `search.json` can be `{"name":"Summer launch","limit":100}`. For the budget example, `{"budget":{"daily_spend_limit_micros":50000000}}` sets 50 major currency units per day. Use the currency returned by `account`. Preserve existing settings that the API replaces as a unit, especially nested targeting, bids and creative. Native amounts in these JSON files are already in API units. A daily budget can repeat indefinitely. An archive is irreversible.

## Campaigns, bidding and targeting

- Use `list-campaigns`, `list-ad-groups` (query `campaign_id`) and `list-ads` (query `ad_group_id`). Match by name when supplied, then select the real ID. Array query fields use JSON arrays; the CLI adds brackets and encodes the wire parameters.
- Use `create-campaign`, `create-ad-group` and `create-ad` to create resources individually under selected parents. Status is explicit. For a new advanced hierarchy, create paused entities and use their returned IDs. Each mutation is its own proposal. Use the standard launch flow for a single confirmation on a simple hierarchy or use a bulk job for supported multi-resource changes.
- For lifetime budgets use `budget.lifetime_spend_limit_micros`. Choose exactly one daily or lifetime limit. Conversion campaigns require `bidding_type: "conversions"` and one eligible active standard `conversion_event_setting_ids` entry. The ad group uses click billing. Fixed conversion bidding uses the target CPA in micros. Maximize-conversions uses a daily budget, `strategy: "maximize_conversions"`, and omits the manual bid.
- Use `read get-geo-lookup` with `{"q":"California"}`. Use its IDs under `targeting.locations.include`, geographic exclusions under `targeting.excluded_locations`, and surfaces under `targeting.platforms.included`. Audience inclusion and exclusion use `custom_audiences.ids` and `excluded_custom_audiences.ids` inside `targeting`. For eligible ready audiences, set `bidding_config.custom_audience_bid_multipliers` on the ad group.
- Edit settings via `update-campaign`, `update-ad-group` and `update-ad`. For an existing resource use its `activate-*`, `pause-*`, or `archive-*` action. Activating a parent can start delivery of eligible children.
- If a named pause times out, resume the original receipt. When the target is already paused, execution verifies the status by reading it. For multi-image ads, the helper compares the approved `creative.file_ids` in order with the file IDs returned in `creative.images`.
- Bulk preview and submission use `create-bulk-job`. Set `validate_only: true` for an official validation job. Approval of validation covers only that job. Prepare a fresh proposal with `validate_only: false` to apply mutations. The bulk schema differs from the single-resource schema. Each operation has an `operation_id`, `type` and `input`. Creates require distinct per-operation idempotency keys. Updates require an existing `target_resource_id`. When a submission times out, resume its original receipt. If the target budget, configuration or affected children changed, reconcile the original job and obtain fresh approval for any remaining changes. A job can partially succeed. Poll `get-bulk-job --param job_id=ID`; on completion run `read list-bulk-results --param job_id=ID --all-pages` and inspect each row before reporting success. [Bulk operations](https://developers.openai.com/ads/bulk-api)

## Advertiser accounts and administrator access

Use an account key through `OPENAI_ADS_API_KEY`. For a provisioned partner key or OAuth access token use `OPENAI_ADS_PARTNER_KEY` or `OPENAI_ADS_OAUTH_TOKEN`, list accessible accounts with `read list-ad-accounts`, then set `OPENAI_ADS_ACCOUNT_ID` to select one. Supply one credential mode at a time. The selected account is bound to the proposal. `read get-ads-oauth-me` identifies an authorized partner user. `create-ad-account-creation-session` uses that user and returns a private hosted onboarding URL. The advertiser completes OpenAI’s hosted steps. The skill consumes previously issued partner credentials.

Use `update-ad-account` for brand settings and `pause-ad-account` or `activate-ad-account` for account-wide delivery. Use `read get-ad-account-spend-limit-windows` to inspect period limits, daily rules, revision and permitted edits. Dated limits can be created, updated and deleted. Daily proposals require `expected_revision` from the account read. For multiple daily rules, supply the target `window_id` to edit or remove it. An explicit null creates a new rule. The helper verifies the affected ID in the returned and current rule sets. Show amount, dates, currency and scope. Use `read list-audit-logs` with supported actor, resource and time filters.

For account activation, show the names, IDs and daily or lifetime budgets of all configured active campaigns in the preview. Execution rereads every campaign page before submitting activation. A change in the approved list or budgets requires a fresh preview. An older activation receipt without this list also needs a fresh preview before it can authorize a write. If submission was interrupted, resume the original receipt first to check the current status.

`create-api-key`, `create-conversion-api-key`, `post-product-feed-sftp-access` and `create-ad-account-creation-session` require a new `--secret-output` path on **plan**. Execution writes the native response to this owner-only file. Keep the path in an appropriate private directory and return the path to the operator. If saving the receipt fails after issuance, keep both files and resume the original receipt. It can finish saving the private response without issuing a second credential. For hosted onboarding, present the returned official URL privately to the intended advertiser.

## Lead Sync and Partner Data

**Lead Sync.** Use an enabled account API key or scoped Ads OAuth credential. List subscriptions for the intended account, then get details with the returned `subscription_id`. The list query file contains `{"ad_account_id":"adacct_123"}`. Creating and deleting with OAuth require both Ads admin read and write scopes.

```bash
bash <skill-path>/scripts/chatgpt_ads.sh read list-lead-sync-subscriptions --query ./account.json
bash <skill-path>/scripts/chatgpt_ads.sh read get-lead-sync-subscription --param subscription_id=SUBSCRIPTION_ID
bash <skill-path>/scripts/chatgpt_ads.sh plan create-lead-sync-subscription --body ./webhook.json --secret-output ./webhook-credentials.json --state ./subscribe.json
bash <skill-path>/scripts/chatgpt_ads.sh execute --state ./subscribe.json --confirm FINGERPRINT
bash <skill-path>/scripts/chatgpt_ads.sh plan delete-lead-sync-subscription --param subscription_id=SUBSCRIPTION_ID --state ./unsubscribe.json
```

Supply the account and exact HTTPS `destination_url` in the private body. For example, `{"ad_account_id":"adacct_123","destination_url":"https://crm.example.com/webhooks/leads"}`. An optional `signing_secret` uses the documented `whsec_` format. Omit it to request a managed secret. The preview shows the host and binds the complete body by digest. Review the exact URL in the protected input file before approving delivery of leads. Execution saves the native response including the signing secret in the owner-only output file. Use the returned ID and status to inspect the subscription. After an uncertain create, reuse the original receipt, request body and idempotency key. Show the ID and effect on future deliveries before confirming the separate deletion receipt.

**Partner Data.** Use an enabled API key via `OPENAI_ADS_PARTNER_KEY` or `OPENAI_ADS_API_KEY` (in this order). The upload API accepts API-key authentication. The receipt binds to that credential and the precise snapshot manifest. The account selector and OAuth token apply to other advertiser operations.

```bash
bash <skill-path>/scripts/chatgpt_ads.sh plan create-partner-data-upload --body ./manifest.json --secret-output ./upload-instructions.json --state ./upload-session.json
bash <skill-path>/scripts/chatgpt_ads.sh execute --state ./upload-session.json --confirm FINGERPRINT
bash <skill-path>/scripts/chatgpt_ads.sh read get-partner-data-upload --param upload_id=RETURNED_UPLOAD_ID
```

Build the manifest from the intended Parquet file. Supply `data_type` as `identity_graph`, `snapshot_date` as YYYY-MM-DD, `file_name` as a .parquet basename, the integer `file_size_bytes` (1–107374182400) and the lowercase hexadecimal `sha256` of the contents. Creating a session submits only these five fields. The private output holds the signed `upload_url`, expiry, `upload_method` and `upload_headers` for the separate file transfer. Check status using the returned `pdu_` ID. A lost create response without an ID requires reconciliation before retrying, since the API declares no idempotency key on this route. [Official request and response schemas](https://developers.openai.com/ads/openapi.json)

## Creative, audience data and feeds

- Submit a local creative via `plan upload-image --file ./shoe.png --state ...`, or pass a body containing `image_url`. For brand icons use `purpose: "account_favicon"`. Use the returned file IDs in the approved creative. Multi-image cards use `creative.type: "chat_card"` and an ordered array of 4–6 eligible square `creative.file_ids`. Replace creative with `update-ad`; include the necessary fields for its creative type. Tracking parameters use `landing_page_configuration.query_string_template` at the campaign, group or ad level.
- For first-party audiences, use consented identifiers authorized for advertising. Upload a CSV/TXT with `plan upload-blob --file customers.csv ...` and use the returned ID and matching file metadata for `create-custom-audience`. Use eligibility filtering in `list-custom-audiences` for the intended targeting use. Add/remove accepts exactly one uploaded file or an inline `identifiers` array. Read the membership revision before changes. Replace uses the complete new file. Merge creates a new union. Read `get-custom-audience-operation` and `list-custom-audience-operations` for asynchronous outcomes. Add/remove operations support resume and cancel by their returned IDs. Use `archive-custom-audience` to archive. [Audience contracts](https://developers.openai.com/ads/custom-audiences)
- Use `create-product-feed`, `list-product-feeds`, `get-product-feed-settings` and `patch-product-feed-settings`. Setting `is_full_refresh: true` enables removal of products omitted from subsequent full uploads. Show that effect explicitly. `post-product-feed-sftp-access` issues or replaces SFTP credentials. Inspect, pause or reactivate access using the named SFTP actions.
- Use `plan upload-feed-snapshot --param feed_id=FEED_ID --file catalog.csv --body remote.json --state ...` for an actual root-directory upload. The body identifies the remote basename, e.g. `{"remote_name":"catalog.csv"}`. The approved content digest and current SFTP destination are rechecked. SSH-key uploads use OpenSSH `sftp` and an SSH agent or `OPENAI_ADS_SFTP_IDENTITY_FILE`. Password uploads use Python `paramiko` and `OPENAI_ADS_SFTP_PASSWORD`. Both require a trusted host key; use `OPENAI_ADS_SFTP_KNOWN_HOSTS` for a dedicated file. Inspect `list-product-feed-uploads` for ingestion and rejected rows. For one Hotel feed, pass `{"inventory_type":"hotel","feed_id":"FEED_ID"}` in the query file. Use `--all-pages` for its full upload history. `patch-product-feed-products` updates supported fields of existing items. `archive-product-feed` archives a feed.
- Query products with `query-product-feed-products` and generic Product/Hotel items with `query-feed-items`. `list-product-reviews` returns review maps; optionally request rejection reasons. Keep native review maps when paginating. Product-feed campaigns use `mode: "product_feed"` and `product_feed_id`; groups can use `product_set` filters. Create a `product_ad_template` ad using feed placeholders. [Product feeds](https://developers.openai.com/ads/product-feeds)
- For enrolled Hotel accounts use `inventory_type: "hotel"`, `schema_profile: "hotel_property_v1"` on feed creation and `inventory_type: "hotel"` on list queries. After SFTP ingestion, use `feed_selection` on the campaign, matching `feed_set` on the group, and an ad template with `{{product.body}}` and `{{product.price}}`. Hotel currently requires US targeting and clicks with manual CPC. Use `create-ad-preview`, `get-hotel-insights` and `get-hotel-insights-timeseries`. [Hotel feed setup and template examples](https://developers.openai.com/ads/hotel-feeds)

## Pixel, events, attribution and diagnosis

1. Use `create-conversion-source` for a web pixel. Keep its source resource ID and its separate public Pixel ID. Use the source resource ID for `create-conversion-event-setting`. Inspect via `list-conversion-sources` and `list-conversion-event-settings`.
2. Generate the site snippet with `pixel-snippet --pixel-id PIXEL_ID --output pixel.html`. Install it in the intended pages’ head using the website’s deployment process. Where measurement consent is needed, use `--consent-required` and call `oaiq("consent", true)` after consent. Emit real business events in the relevant site handler. A purchase example is `oaiq("measure", "order_created", {type: "contents", amount: amountInMinorUnits, currency: currencyCode}, {event_id: orderEventId})`. Check recent receipt with `list-conversion-events` and query `pid`. [Pixel installation](https://developers.openai.com/ads/measurement-pixel)
3. Put the dedicated Conversions API credential in `OPENAI_ADS_CAPI_KEY`. Use `plan send-conversion-events --query pixel.json --body events.json --state ...`. The query is `{"pid":"PIXEL_ID"}`. Set `validate_only: true` for a validation batch and preview a new batch for production. Private request files are digest-bound. Each event needs its real stable `id`, `type`, `timestamp_ms` and matching `data`. Web events carry the original `source_url`; include an actual `oppref` when available. Normalize and hash the documented matching fields before sending. Reuse the same Pixel ID, event type and event ID across browser and server for deduplication. Use a stable `integration_source` when sending events for a client. [Conversions API](https://developers.openai.com/ads/conversions-api)
4. For channel-native attributed purchases, use `report --options metrics.json`. Example options: `{"fields":["campaign_id","spend","conversions","order_created_attributed_sales","order_created_attributed_sales_currency","order_created_roas"],"attribution_window_days":30,"view_through_attribution_window_days":1,"attribution_time_basis":"ad_event_time"}`. Use the native null when value or denominator is unavailable. For event-specific results run `read post-conversion-insights --body report.json` with one full-day account-local range (exclusive end for this POST) and optionally `include: ["attributed_events"]`. GET delivery date ranges use inclusive dates. Report filters, sorting, time granularity, zero-row inclusion and segment compatibility depend on the selected fields. [Reporting](https://developers.openai.com/ads/reporting)
5. Diagnose an existing ad with `read get-ad --param ad_id=ID --query include.json`, where the query is `{"include":["serving_issues"]}`. Inspect its parent group/campaign and account review, budget, schedule and spend limits. For eligible accounts, read `get-ad-group` with `include: ["bid_too_low"]`, or `get-landing-page-crawler-evidence` for the ad. For provisioned partner eligibility jobs, submit the approved synthetic evaluation with the current account association, consent and enrollment revision, then read its job and results. [Troubleshooting](https://developers.openai.com/ads/troubleshooting)

For a site with multiple authorized pixels, repeat `--pixel-id` on the same command. The snippet loads the SDK once. Route an order to one pixel with `oaiq("measureSingle", pixelId, "order_created", data, {event_id: orderEventId})`. The `measure` command sends to every initialized pixel. [Multiple pixels](https://developers.openai.com/ads/multiple-pixels)

Sites that render a fallback for browsers without JavaScript can include the following in the page body after the site's consent check. Substitute the real Pixel ID at render time. For an order event, also supply the real event ID, integer amount in minor units, and currency. Encode each query value and escape the resulting URL for HTML. [Image tag](https://developers.openai.com/ads/image-tag)

```html
<noscript>
  <img src="https://bzr.openai.com/v1/sdk/events?pid=PIXEL_ID&amp;event=page_viewed&amp;data%5Btype%5D=contents"
       width="1" height="1" alt="" style="display:none">
</noscript>
```
