# Facebook page/profile post inputs

The empty top-level required list is qualified by allOf/anyOf: at least one of url/pageId is required. Both may be supplied, without inventing precedence or a cross-resolution call. The helper preserves identifiers, validates declared types/enums/bounds and checks URL envelopes. Backend validation owns detailed path/identity/date/feature combinations. Omitted fields stay omitted.

| JSON / CLI | Type | Meaning |
| --- | --- | --- |
| `url` / `--url` | string | Full Facebook page/profile URL. Profile share links at https://www.facebook.com/share/… are accepted per description. Preserve path/query/fragment without expanding locally, deriving an ID or fetching the profile. The helper requires HTTP(S), Facebook domain, a path and no whitespace/credentials; actual identity/path resolution belongs to backend. |
| `pageId` / `--pageId`, `--page-id` | string | Facebook profile page ID. Keep exact long/leading-zero string. No numeric pattern declared; never convert to integer or map to profile_id/page_id/handle. URL is not additionally required. |
| `async` / `--async` | boolean/integer/string | Exact JSON variants: booleans, integers 0/1, strings "true"/"false"/"1"/"0". CLI true/false becomes boolean, 1/0 integer. Independent of fixed wrapper response_mode=json. |
| `since` / `--since` | string | Inclusive YYYY-MM-DD midnight UTC or ISO timestamp. Older posts omitted; an older non-pinned post ends walk with stopped_at=since and no next cursor. Pins never end it. CLI --published-after/--start-date/--from-date map here. |
| `until` / `--until` | string | Inclusive whole UTC date or ISO timestamp. Filters newer rows, keeps undated rows and does not stop walk. CLI --published-before/--end-date/--to-date map here. |
| `cursor` / `--cursor` | string | Exact continuation token from a compatible prior response. Omit for page 1; never decode, construct, increment or convert to integer. Explicit next page uses new state/client ID and unchanged identifiers/options. |
| `include` / `--include` | string engagement | Explicit single-token backend join. Fills shares on posts, views/duration on reels; no automatic enabling, channel token or CSV combinations. Preserve native data.hydration and nulls. |
| `stop_at_id` / `--stop-at-id` | string | Known newest post.id or post.url. Stop before a non-pinned match and following rows: no next cursor, stopped_at=known_id. Pins never trigger it. If absent, full page/cursor remains. End means exhaustion; null means more may remain. IDs/URLs preserved verbatim. |
| `recent_days` / `--recent-days` | integer 1–3650 | Keep last N days' posts and stop pagination at older posts, normal page price unchanged. Remains integer rather than a recomputed since date or max_age_days. Detailed interaction/precedence with other boundaries and pin handling for this option are not supplied. |

One invocation returns one page and never automatically follows a cursor, resolves a share link, looks up an ID/profile or downloads media. A READY task is not full-history completion while continuation remains. Trust native stop/cursor metadata instead of local pin/date filtering. Until can leave empty pages with continuation. Filtering does not erase fetched-page price. A saved completed state returns its snapshot; an explicitly requested new refresh/daily check uses new state/client ID and chosen since/recent_days/known-post boundaries.

Include enrichment is described as holding 1 credit per row (illustrated as 3 a page), refunding cache hits/unfilled rows and keeping only fresh fills, with page maximum 4 credits and usually less. No public share count stays null and is described as free. Event-link rows are not looked up. Fresh lookup latency is described as 2–7 seconds, never more than 12, with no delay when cached. Preserve actual data.hydration rows/credits held/kept/time; do not infer a fixed row count, recompute billing, fetch event links or requery unresolved/null metrics. Existing shares/media/reel fields remain native without enrichment; include is not a prerequisite for returning any already-present value.

Static date aliases are CLI-only; JSON accepts the exact declared fields. Resolve requested relative date aliases before invoking with timezone/date context and preserve the chosen literal on retries. Recent_days remains the original integer; do not guess precedence when since is also present. No query, profile_id/page_id, handle, labels, judgments, fit, relevance, dry_run, trim, limit, sort, after, location, max_age_days or download controls are declared. Native pageId casing must survive serialization. Do not borrow fields from the other Facebook helpers or invent a schema for an alternate route.
